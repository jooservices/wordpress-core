# Showcase content matrix

**Status:** Owner approval and manual checks are pending. The rows define the contract for the showcase generator (JOOS-93) and the data-driven browser suite (JOOS-97); this document does not claim the generated site or those tests already exist.

The authoritative row data is [`tests/showcase/matrix.json`](../../tests/showcase/matrix.json). Each row has a stable id and content key, required content, expected local URL and HTTP status, specification ids, planned automated test id, manual checker, and verification profiles. The validator fails when any required field or source spec mapping drifts.

## Coverage environments

Every row references `ltr` and `rtl`. The Chinese language row also references `cjk`. Each profile is the full Cartesian product of browser engine, viewport, colour scheme, and site language. A profile also carries the 12-width no-overflow sweep from 320px to 3840px.

| Profile | Automated browser engines | Required viewport sizes | Colour schemes | Site locales |
| --- | --- | --- | --- | --- |
| `ltr` | Chromium, WebKit, Firefox | phone 390×844, tablet 820×1180, desktop 1440×900 | dark, light, ocean, forest, paper | en, vi |
| `rtl` | Chromium, WebKit, Firefox | phone 390×844, tablet 820×1180, desktop 1440×900 | dark, light, ocean, forest, paper | ar, he_IL |
| `cjk` | Chromium, WebKit, Firefox | phone 390×844, tablet 820×1180, desktop 1440×900 | dark, light, ocean, forest, paper | zh_CN |

Product browser targets recorded for the manual audit are Chrome and Edge desktop (current and previous stable), Safari desktop 16.4+, iOS Safari 16.4+ on a device, Firefox ESR and current stable, and current Android Chrome on a device. The automated engines are Chromium, WebKit, and Firefox; exact product versions and real-device evidence remain manual audit evidence.

For RTL runs, set the WordPress site locale to `ar` and `he_IL` in separate runs and assert `is_rtl()` plus `html[dir="rtl"]`. RTL profiles apply to every matrix row, not only the dedicated Arabic/Hebrew content rows. The Chinese sample is additionally checked with the `zh_CN` locale.

## Generated-site verification

Run the static contract check with the repository Node runtime:

```sh
bash docker/scripts/runtime.sh node tools/validate-showcase-matrix.mjs
```

This verifies JSON structure, unique ids/content keys, required test and manual-check references, every id in the checked-in design checklist, the required browser/environment profiles, the human-readable table, and any implemented test-file references. Without an inventory it does not claim that content is present in a running site.

After JOOS-93 creates the showcase inventory, verify every generated row key and observed route with:

```sh
bash docker/scripts/runtime.sh node tools/validate-showcase-matrix.mjs --inventory <generated-inventory.json>
```

The inventory is JSON schema version 1 with an `entries` array. Each row must include its `contentKey`, `status: "present"`, the exact `expectedUrl`, and the observed `httpStatus`. This includes hidden draft/private/scheduled records, whose content must exist while the anonymous route returns the expected 404.
